# Antigravity Agent Manager를 활용한 병렬 에이전트 실행

## 1. Antigravity의 가장 강력한 기능인 Agent Manager 뷰를 활용하여 각 역할을 수행할 에이전트들을 동시에 병렬로 실행하라

### 매니저(Manager) 역할 수행: Antigravity의 철학에서 'Chief Manager'의 역할은 시스템을 지휘하는 **개발자(Architect)**와 메인 워크스페이스를 관장하는 메인 에이전트의 결합으로 이루어집니다

### 비동기 병렬 실행: Agent Manager 패널을 열고 각 폴더별로 독립된 에이전트 세션을 시작하라

### Agent 1 (Backend): DART API를 연결하고 파이프라인을 구축하도록 명령하라

### Agent 2 (Ontology): 백엔드가 가져온 데이터를 바탕으로 지식 그래프 추출 스크립트를 작성하게 하라

### Agent 3 (Frontend): 프론트엔드 UI/UX 템플릿을 스캐폴딩(Scaffolding)하도록 지시하라

### Agent 4 (Fact-check): 기사 초안의 숫자, 맞춤법, 언론사 윤리 강령 위반 여부를 최종적으로 교열하도록 명령하라

### Agent 5 (GEO): 기사 초안의 숫자, 맞춤법, 언론사 윤리 강령 위반 여부를 최종적으로 교열하도록 명령하라

## 2. 표면(Surfaces)별 맞춤형 자동화 실행

각 에이전트는 Antigravity에 내장된 고유한 권한을 활용해 자신의 작업을 검증합니다.

### Terminal 통제 (Backend / Ontology / Security)

### 백엔드 및 보안 에이전트는 직접 터미널 환경에 접근하여 Python 스크립트를 실행하고, DB를 띄우며(Docker), 패킷이나 에러 로그를 모니터링합니다. 스스로 로그를 읽고 에러를 디버깅합니다

### Browser 에이전트 활용 (Frontend / Data Viz)

### Antigravity의 Browser Surface를 통해 프론트엔드 에이전트와 데이터 시각화 에이전트가 로컬 서버를 띄운 뒤 직접 크롬(Chrome)을 조작합니다

### 차트가 제대로 렌더링되었는지, 모바일 반응형이 깨지지 않았는지 스스로 브라우저를 스크롤하고 클릭하며 확인합니다

## 3. 아티팩트(Artifacts) 기반의 협업 및 자가 진화 피드백

단순한 코드 수정이 아니라 시스템이 '스스로 진화'하게 만들려면 Antigravity의 아티팩트 및 피드백 시스템을 적극 활용해야 합니다.

### 아티팩트 생성 지시: 에이전트들에게 "작업이 끝나면 결과물(DB 스키마 구조도, 프론트엔드 스크린샷, 기사 초안 텍스트 등)을 Artifact로 남겨라"라고 지시합니다

### 크로스 체킹 (Cross-checking): 예를 들어, 팩트체크 에이전트(Fact-check Agent) 워크스페이스에서 기사 작성 에이전트가 생성한 기사 텍스트 아티팩트를 불러와 검수하게 합니다

### 구글 문서 형태의 피드백 (Self-Improvement): 에이전트가 생성한 아티팩트나 실패한 로그에 대해 개발자(또는 데스크 기자)가 Google Docs 스타일의 코멘트를 남깁니다. Antigravity의 에이전트는 이 피드백을 실시간으로 수용하여 작업을 수정하고, 그 교훈을 해당 디렉토리의 RULES.md나 지식 베이스 파일에 스스로 업데이트하여 다음 작업의 오답률을 낮춥니다
